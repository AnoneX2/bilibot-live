# 提示词目录

这两个文件就是**发送给模型的完整 Prompt**，改完保存即可生效（默认每 2 秒检查一次文件变化，**不用重启**）。
也可以直接打开设置面板（`python -m src.app panel`）在「提示词」页里编辑、校验并预览实际渲染结果。

| 文件 | 作用 |
|---|---|
| `system.md` | 默认人设：角色、性格/语气、输出格式、硬性规则。**语气风格直接写在里面，随便改。** |
| `user.md` | 每次请求的动态内容：直播间信息、主播语音转写、弹幕氛围、触发原因。 |

## 多套人设

除了默认的 `system.md`，还可以放多套人设，BOT 会自动发现：

| 布局 | 例子 | 说明 |
|---|---|---|
| 单文件 | `persona.md` | 只写 system（角色/语气/规则），动态内容共用 `user.md` |
| 目录 | `persona/system.md` + `persona/user.md` | 该人设独立使用一套模板 |

- 文件名不要以 `system` 开头（会被当成副本忽略），`README.md`、`user.md` 也不是人设。
- 设置面板「提示词」页右上角有「新建人设」，选单文件/目录、填个名字就能创建（可复制当前人设内容），不用手动建文件。
- 在设置面板「直播间」的「人设」下拉里选择即可；手写配置用 `prompt_dir: "persona.md"`。
- 单文件人设只作为 system，不能写 `{{transcript}}` 这类 user 变量（会报错）。

- 以 `#` 或纯文本随意编辑，不需要懂代码。
- `{{变量}}` 是程序自动填充的占位符，**不要删掉不认识的变量**，否则会缺内容。
- 改了占位符或写错变量名时，启动检查（`python -m src.app check`）会给出提示。
- 想给某个直播间单独一套人设：在 `config.yaml` 的 `app.rooms` 里给该房间加
  `prompt_dir: prompts_room2`，然后复制本目录改成自己的内容。

## system.md 可用变量

| 变量 | 说明 |
|---|---|
| `{{max_chars}}` | 回复字数上限（来自 `reply.max_chars`，默认 30） |

## user.md 可用变量

| 变量 | 说明 |
|---|---|
| `{{title}}` | 直播间标题 |
| `{{alias}}` | 直播间别名（配置里的 alias） |
| `{{alias_part}}` | 形如「（别名）」，没有别名时为空 |
| `{{bot_name}}` | 机器人自己登录的 B 站账号名（让它认得自己）；未登录时是「（未登录）」 |
| `{{clock}}` | 当前时间 `HH:MM:SS` |
| `{{frame_desc}}` | 是否附带了画面，以及画面是几秒前抓的 |
| `{{timeline}}` | 本场「语音 + 弹幕 + 自己说过的话」按时间合在一起的记录（`[语音]` / `[弹幕]` / `[我说]`；默认模板用这个；超预算时保留最近内容并标注省略条数） |
| `{{transcript}}` | 只有语音转写（兼容旧模板用；新模板建议直接用 `{{timeline}}`） |
| `{{danmaku}}` | 只有弹幕（兼容旧模板用；默认只作氛围参考，只有被 @ 时才用于触发回应） |
| `{{trigger}}` | 本次触发原因，例如「主播刚说了：……」 |
| `{{max_chars}}` | 回复字数上限 |
| `{{room_id}}` | 直播间房间号 |

## 关于顺序（会影响 API 费用）

大模型服务端的缓存是**前缀缓存**：只有和上一次请求「从头逐字节相同」的部分才算命中。
所以默认模板把**稳定内容放前面**（直播间标题 → 本场记录），**每次都变的内容放后面**
（当前时间、画面、本次触发）。自己改模板时也请保持这个顺序，否则缓存全部失效、
费用按全价算；`python -m src.app check` 不会检查这一点，但改动很容易白花钱。

## 改 Prompt 的建议

1. **风格写在 system.md 的「人设与语气」段**，越具体越稳：可以写口头禅、句长偏好、禁用词。
2. **别在 system.md 里写太长**：超过几百字会显著增加成本与延迟。
3. 想让它更少说话：把「沉默是可以的」写得更强硬，或调大 `reply.speech_trigger_interval_sec`。
4. 想让它更像真人：在 system.md 里加 2–3 条**正面例句**（不要写负面例句，模型容易照抄）。
5. 弹幕放在 user.md 的「氛围」段；默认不要写成「回答观众的问题」。被 @ 的回应由 `{{trigger}}` 里的描述单独说明（见 `system.md` 第 8 条），不需要在模板里再写一遍。
6. 本项目不做听歌识曲，system.md 里已写明「不要报歌名/歌手/BGM」，不要删掉这条。

## 被 @ 时的回应

程序只把「回复了 BOT 的弹幕」当作触发（B 站把 @ 存在 `reply_mid` 字段里，不在正文；
其余弹幕仍然是氛围），
触发原因会填进 `{{trigger}}`，形如：

```
观众「小明」在弹幕里 @ 了你，原话：「@某某 这波怎么看」。这属于被点名：这一条请回应这位观众……
```

频率由 `reply.mention_enabled / mention_min_interval_sec / mention_max_per_hour` 控制，
和普通回复一样要过内容闸门（长度、@ 反带、黑名单、重复度）。`system.md` 第 8 条说明了这个例外；
不喜欢这种交互可以整条删掉，并把 `mention_enabled` 设为 `false`。
